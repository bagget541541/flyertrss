# 公众号贴图验收（wechat-image-qa-reviewer）

## 任务目标

对输入的公众号推文配图做**六类视觉质量检查**，输出 Markdown 验收报告。

每条问题须包含：**图片编号 + 区域描述**（如"图3 右下角文字区"）、问题描述、修改建议。

**输入**：一张或多张图片（PNG / JPG / WEBP）  
**输出**：`image_qa_MMDD.md`（Markdown 验收报告）

---

## 工作流

### Step 1：建立整体印象

将所有图片**通览一遍**，建立以下认知后再逐项检查：

- 这组图的**整体设计风格**（极简 / 杂志风 / 信息图 / 配图说明型 / 纯文字卡片……）
- 预期的**目标受众和阅读场景**（手机竖屏阅读 / PC 端 / 印刷）
- 图片**总数量及编号**（按上传顺序标记为图1、图2……）

记录在报告头部"设计类型"字段，作为后续判断"是否合理"的基准。

---

### Step 2：六类检查

#### 检查 A — 整体风格一致性

适用于多张图组成的系列推文配图（单张图跳过 A 类，记录说明）。

| 检查项 | 说明 |
|--------|------|
| 主色调统一 | 各图主色 / 强调色是否一致；是否出现突兀的跳色 |
| 字体体系 | 标题字体、正文字体是否跨图保持一致；有无混用多种无关字体 |
| 圆角 / 边框风格 | 卡片、标签、图框的圆角弧度是否统一 |
| 间距体系 | 各图的边距、元素间距是否视觉上相当；有无某张明显偏紧或偏松 |
| 装饰元素语言 | 分割线、图标、标注气泡等装饰元素风格是否同源 |
| 版式方向 | 同系列图的版式方向（竖/横/正方）是否一致 |

**标记格式**：`[风格-A01]` 涉及图号 → 问题 → 建议

---

#### 检查 B — 文字可读性

| 检查项 | 说明 |
|--------|------|
| 最小字号 | 正文字号是否过小（手机阅读场景下，图片尺寸 1080px 宽时正文建议 ≥ 28px） |
| 文字与背景对比度 | 浅色字在浅背景 / 深色字在深背景上是否难以辨认 |
| 渐变背景叠字 | 文字叠在渐变或图案背景上时，是否有描边 / 蒙层保障可读性 |
| 文字压图 | 文字与背景图片元素重叠，导致识别困难 |
| 行距与字间距 | 行距过密（段落挤在一起难以区分）或过稀（撑开后视觉松散） |
| 截断与溢出 | 文字是否被边框 / 容器截断，是否溢出设计边界 |

**标记格式**：`[可读-B01]` 图号 + 区域 → 问题 → 建议

---

#### 检查 C — 边界与溢出

| 检查项 | 说明 |
|--------|------|
| 内容超出画布 | 文字、图形、装饰元素是否被图片边缘截断 |
| 安全边距不足 | 内容贴近图片四边，手机端显示时有被系统 UI 遮挡风险（建议四边留 ≥ 3% 安全边距） |
| 图层遮挡 | 前景元素意外覆盖关键文字或主视觉 |
| 拼接缝隙 | 多张拼接图片之间存在白缝或错位 |

**标记格式**：`[边界-C01]` 图号 + 边/角 → 问题 → 建议

---

#### 检查 D — 紧凑度与呼吸感

过于紧凑和过于空旷都是问题，目标是"信息密度适合手机竖屏连续阅读"。

| 问题类型 | 判断依据 |
|---------|---------|
| **过度紧凑** | 文字段落间距 < 字号的 0.5 倍；多个信息模块无分隔直接堆叠；图与文无间距直接接触 |
| **大片空白** | 某区域留白 > 整图面积 25% 且无视觉或功能意图；文字区域内出现不合理的大段空行 |
| **空白分布不均** | 上半部拥挤、下半部大面积留白（或反之）；左右两侧重量感失衡明显 |
| **局部呼吸感消失** | 某一信息块内部各元素无间距，整体黏连成一块 |

**标记格式**：`[布局-D01]` 图号 + 区域 → 问题类型（紧凑/空白/失衡）→ 建议

---

#### 检查 E — 元素堆叠与层次

| 检查项 | 说明 |
|--------|------|
| 无意义堆叠 | 多个装饰元素、图标、标签重叠，形成视觉噪音 |
| 主次层次模糊 | 标题、副标题、正文视觉权重相近，无法快速抓住重点 |
| 图标与文字混乱排列 | 图标大小不一、与文字对齐方式混乱 |
| 信息组未分组 | 属于同一主题的内容未在视觉上归组，与不相关内容视觉距离相当 |
| 装饰喧宾夺主 | 装饰元素视觉权重高于核心文字/数据 |

**标记格式**：`[层次-E01]` 图号 + 区域 → 问题 → 建议

---

#### 检查 F — 图文配合

| 检查项 | 说明 |
|--------|------|
| 配图与文字内容无关 | 配图情绪 / 内容与旁边文字描述明显不符 |
| 图片模糊或像素低 | 图片明显欠缺清晰度，手机端放大后失真 |
| 人物 / 主体被截断 | 人物头部、产品核心部位被边框切断 |
| 图片比例变形 | 图片被非等比缩放，出现拉伸或压缩 |
| 图片色调与整体不协调 | 配图色温、饱和度与设计整体风格明显冲突（如暖色系设计中出现冷色图） |

**标记格式**：`[图文-F01]` 图号 + 区域 → 问题 → 建议

## 输出规范

- 每类问题**实事求是**：找到几条写几条，没有不强凑
- 问题定位用**图编号 + 视觉区域描述**（如"图3 左上角标题行"），不用坐标数字
- 修改建议**具体**：说"将字号从约16px增大至24px"而非"建议增大字号"
- 总体评估**不超过3句**，直接点明核心问题
- **单张图时**：跳过 A 类，其余五类正常检查

---

## 常见场景适配

| 图片类型 | 重点检查项 |
|---------|-----------|
| 纯文字卡片（金句图、引用图） | B（可读性）> D（布局）> A（风格）> E（层次）|
| 数据信息图（图表、数字大图） | E（层次）> B（可读性）> D（布局）> F（图文）|
| 图文混排长图 | C（边界）> D（布局）> F（图文）> B（可读性）|
| 封面大图 | F（图文）> B（可读性）> C（边界）> E（层次）|
| 步骤/流程图 | E（层次）> D（布局）> B（可读性）> C（边界）|
| 活动海报 | A（风格）> C（边界）> B（可读性）> D（布局）|

---

## 检查标准参考值（手机端 1080px 宽图）

| 指标 | 建议值 |
|------|--------|
| 正文最小字号 | ≥ 28px（约 1080px 宽） |
| 标题最小字号 | ≥ 40px |
| 四边安全边距 | ≥ 32px（约 3%） |
| 段落行距 | 字号 × 1.5 ~ 1.8 |
| 同模块内元素间距 | ≥ 8px |
| 不同模块间距 | ≥ 标题字号的 1 倍 |

*以上为经验参考值，实际可根据设计风格适度调整；极简风可放宽留白，信息密集图可适度收紧。*

## 部署方案

### 依赖分析

六类检查对 LLM 视觉能力的依赖程度不同：

| 检查类 | 依赖类型 | 说明 |
|--------|---------|------|
| A 风格一致性 | **强依赖 LLM** | 跨图主观感知，规则无法替代 |
| B 文字可读性（对比度/压图） | **强依赖 LLM** | 需理解文字与背景的语义关系 |
| B 文字可读性（字号/截断） | **可脚本辅助** | Pillow 可做像素级边距检测 |
| C 边界与溢出 | **可脚本辅助** | 边距、出血检测可量化 |
| D 紧凑度与呼吸感 | **部分依赖 LLM** | 空白面积可测量，分布合理性需视觉判断 |
| E 元素堆叠与层次 | **强依赖 LLM** | 主次判断纯属语义理解 |
| F 图文配合（相关性） | **强依赖 LLM** | 图文语义关联无法本地判断 |
| F 图片模糊度 | **可脚本辅助** | OpenCV Laplacian 方差检测 |

**结论**：A/E/F（相关性）三类强依赖视觉 LLM，无法绕过；B/C/D/F（模糊）可用本地脚本补充或替代。

---

### 推荐方案

#### 方案一：纯 API 调用（最省事）

直接调用支持多图输入的视觉 LLM，六类检查一次完成。

**推荐模型（按优先级）**：

| 模型 | 接入方式 | 免费额度 | 适用场景 |
|------|---------|---------|---------|
| **Gemini 2.0 Flash** | Google AI Studio | 每天 1500 次，长期免费 | 网络可访问 Google 时首选 |
| **Qwen-VL-Max** | 阿里云 DashScope | 新用户约 100 万 token | 国内网络、中文排版场景 |
| **Claude Sonnet**（本 skill） | Anthropic API / claude.ai | 按用量计费 | 精度最高，适合重要稿件 |

**Gemini 2.0 Flash 接入示例**（需 `pip install google-generativeai`）：

```python
import google.generativeai as genai
from PIL import Image

genai.configure(api_key="YOUR_KEY")  # aistudio.google.com 免费申请
model = genai.GenerativeModel("gemini-2.0-flash")

images = [Image.open(f"图{i}.png") for i in range(1, 6)]
prompt = open("prompt.txt").read()  # 将本 SKILL.md 的检查逻辑提炼为 prompt

response = model.generate_content([prompt] + images)
print(response.text)
```

多图直接塞入列表，Gemini 原生支持跨图关联分析（A类风格一致性效果好）。

**Qwen-VL-Max 接入示例**（复用 openai 包，`pip install openai`）：

```python
from openai import OpenAI
import base64

client = OpenAI(
    api_key="YOUR_DASHSCOPE_KEY",  # dashscope.aliyun.com 申请
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"
)

def encode(path):
    with open(path, "rb") as f:
        return base64.b64encode(f.read()).decode()

content = [{"type": "text", "text": prompt}]
for i in range(1, 6):
    content.append({
        "type": "image_url",
        "image_url": {"url": f"data:image/png;base64,{encode(f'图{i}.png')}"}
    })

response = client.chat.completions.create(
    model="qwen-vl-max",
    messages=[{"role": "user", "content": content}]
)
print(response.choices[0].message.content)
```

接口走 OpenAI 兼容协议，换 base_url 即可，无需额外学习成本。

#### 方案二：脚本 + LLM 组合（成本最低）

用本地脚本承担可量化的检查项，LLM 只处理需要视觉理解的部分，API 调用量减少约 40%。

```
输入图片
    │
    ├─→ 本地脚本（Pillow + OpenCV）
    │       ├─ 边距检测 → C类结果
    │       ├─ 模糊度检测（Laplacian方差）→ F类部分结果  
    │       └─ 主色提取对比 → A类粗筛（跨图色差过大时标记）
    │
    └─→ LLM（Gemini Flash / Qwen-VL-Max）
            ├─ A类：风格一致性（精判）
            ├─ B类：文字可读性
            ├─ D类：布局呼吸感
            ├─ E类：元素层次
            └─ F类：图文语义相关性
    │
    └─→ 合并输出验收报告
```

本地脚本核心片段：

```python
import cv2
import numpy as np
from PIL import Image
from colorthief import ColorThief

def check_blur(path, threshold=100):
    """模糊度检测，返回值越低越模糊"""
    img = cv2.imread(path, cv2.IMREAD_GRAYSCALE)
    score = cv2.Laplacian(img, cv2.CV_64F).var()
    return score < threshold  # True 表示模糊

def check_margin(path, min_ratio=0.03):
    """检测四边是否有足够安全边距（粗检：边缘像素是否全为背景色）"""
    img = np.array(Image.open(path).convert("RGB"))
    h, w = img.shape[:2]
    margin = int(min(h, w) * min_ratio)
    edges = {
        "top": img[:margin, :],
        "bottom": img[-margin:, :],
        "left": img[:, :margin],
        "right": img[:, -margin:]
    }
    # 判断边缘区域色彩方差（低方差=纯色边距，高方差=有内容）
    return {k: v.std() > 20 for k, v in edges.items()}  # True 表示有内容贴边

def extract_main_color(path):
    """提取主色用于跨图一致性粗筛"""
    return ColorThief(path).get_color(quality=1)
```

依赖安装：`pip install opencv-python pillow colorthief`

#### 方案三：完全本地（无网络依赖）

视觉 LLM 本地部署，适合对数据隐私要求高或完全离线场景。

| 模型 | 显存要求 | 部署方式 | 视觉能力评估 |
|------|---------|---------|------------|
| **Qwen2-VL:7b** | 8GB | `ollama pull qwen2-vl:7b` | 中等，中文排版场景可用 |
| **InternVL2-8B** | 10GB | HuggingFace + transformers | 中等偏上，性价比最高 |
| **LLaVA-13B** | 14GB | Ollama 或 llama.cpp | 较弱，不推荐用于细节判断 |

注意：本地模型对 A类（风格一致性）和 E类（主次层次）的主观判断准确率比云端模型低明显，建议结合方案二的本地脚本做粗筛，再用本地 LLM 做精判。

Ollama 调用示例：

```python
import ollama
import base64

images_b64 = [base64.b64encode(open(f"图{i}.png","rb").read()).decode() for i in range(1,6)]

response = ollama.chat(
    model="qwen2-vl:7b",
    messages=[{
        "role": "user",
        "content": prompt,
        "images": images_b64
    }]
)
print(response["message"]["content"])
```

### 方案选型建议

```
有网络（可访问 Google）？
    ├─ 是 → 用 Gemini 2.0 Flash（免费额度足够日常使用）
    └─ 否 → 国内网络？
                ├─ 是 → 用 Qwen-VL-Max（新用户免费额度 + OpenAI 兼容接口）
                └─ 否（完全离线）→ Ollama + Qwen2-VL:7b + 本地脚本辅助
```

**批量验收场景**（每次 5 张以上）推荐方案二（脚本 + LLM 组合），先用脚本过滤明显问题，再用 LLM 精判，单次 API 消耗减少约 40%。
