# BAT 审查修复优先级

日期：2026-08-03
范围：`run.bat`（仅简易模式）与 `微信发布.bat`，以及简易模式实际调用的 `run.py`。

## 优先级结论

| 优先级 | 问题 | 影响 | 修复策略 |
|---|---|---|---|
| P0 | `endlocal` 后读取 `%RC%` | 子脚本失败可能被 BAT 返回为成功，自动化无法感知失败 | 将 `endlocal` 与 `exit /b %RC%` 合并，确保在释放局部环境前展开返回码 |
| P0 | 简易模式忽略封面/公众号文章生成失败 | 关键产物缺失时仍返回成功 | `run.py` 简易模式对关键步骤失败返回非零码，由 `run.bat` 继续传递 |
| P1 | `DETAIL_ARG` 未整体引用 | 路径含空格时 Step 3 参数被拆分 | 改为独立参数传递并对路径加引号 |
| P1 | 详情抓取失败时丢弃部分详情结果 | WAF/网络波动时标题恢复和点评依据全部降级 | 若输出详情文件存在，继续使用该文件；只有没有可用文件时才无详情继续 |
| P2 | `run.bat` 硬编码项目目录 | 换机器或移动目录后无法运行 | 使用 `%~dp0` 计算脚本目录 |
| P2 | `LOG_FILE` 从未写入 | 预期的单次运行日志实际不存在 | 将脚本和子进程输出写入该日志，同时保留终端输出 |
| P2 | 部分早退路径不写 `history.log` | 失败记录不完整 | 统一经过日志收尾逻辑，至少记录步骤与返回码 |

## 实施顺序

1. P0：先保证失败可被正确返回，避免后续修复无法被调度系统识别。
2. P1：修复跨环境参数传递和部分结果复用，降低发布链路脆弱性。
3. P2：处理可移植性与日志完整性，不改变业务流程。

## 验收标准

- 任一关键子步骤失败时，`run.bat` 和 `微信发布.bat` 返回非零码。
- 简易模式的封面或公众号文章生成失败时，`run.py` 返回非零码。
- 带空格的详情文件路径可被 Step 3 正确接收。
- 详情抓取部分失败但生成了详情 JSON 时，Step 3 仍使用该 JSON。
- `run.bat` 可从任意当前目录启动，并以 BAT 所在目录为项目根目录。
- 每次运行都有对应单次日志和 `history.log` 记录。
