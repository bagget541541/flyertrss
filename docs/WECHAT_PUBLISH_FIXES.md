### 1. 银行权益和时间判断过于确定

涉及“通常次日到账”“数据同步需 1-3 个月”“制卡通常需 3-5 个工作日”等表述。此类内容可能受卡种、渠道、活动批次和银行规则影响，存在时效性和个体差异。

**建议方案**：暂不改动现有生成逻辑。后续如处理，统一改为“论坛经验 + 以官方规则为准”的弱结论表达；没有可靠来源时删除具体天数和确定性建议。

### 2. 原帖事实、编辑推断和建议混在一起

当前编辑点评通常在同一段中同时包含原帖事实、原因推测和行动建议，读者不容易判断信息来源和可信程度。

**建议方案**：暂不改动现有点评格式。后续如处理，可采用“原帖提到 / 可能原因 / 建议”三层结构，但不强制增加显式标签，避免回到此前过于模板化的点评格式。

### 3. 未验证的卡片推荐表达较确定

部分点评直接推荐具体卡片，或使用“值得保留”“适合作为里程补充”等普适性判断，但原帖信息可能不足以支撑结论。

**建议方案**：暂不改动现有内容。后续如处理，改为条件化表达，强调年费、消费门槛、出行地点和里程需求等适用条件，并注明属于论坛讨论方案，不代表统一推荐。

### 4. 栏目分类与内容不完全匹配

“现在兴业东航精英白积分多久到账呢？”被放在“权益变更”栏目，实际更接近权益到账或使用疑问，不属于明确的权益规则变更。

**处理结果**：已在 `llm_daily_gen.py` 中增加分类边界：明确提问、求助、咨询优先归入“疑问求助”；“权益变更”限定为已发生或明确公告的规则变化。同时增加输出后确定性校正，识别“多久到账/未到账/怎么/是否/哪个/请教/咨询”等高置信度问句，并将对应帖子移动到“疑问求助”。

### 5. 栏目标题存在前导空格

当前“疑问求助”和“用卡经验”标题前存在一个空格，属于数据清洗或模板拼接问题。

**处理结果**：已补齐 `docx_to_wechat.py` 的栏目图标映射。此前的前导空格实际来自缺少栏目图标后仍无条件输出的模板格式；现在“疑问求助”“用卡经验”“公告通知”等栏目有对应图标，不再出现孤立前导空格。

### 6. 文件是 HTML 片段而非完整文档

当前文件以一个根级 `<div>` 开始，没有 `DOCTYPE`、`head`、字符集和 viewport 声明。这符合“全选复制到公众号编辑器”的用途，但不适合作为独立网页文件。

**建议方案**：暂不处理，保留现有公众号粘贴片段格式。若未来需要浏览器预览或归档，再另行生成完整 HTML 预览版，不改变粘贴版。

### 7. 公众号编辑器可能清洗复杂样式

产物使用了 `display:flex`、`gap`、`position:absolute`、`overflow:hidden` 等样式。公众号编辑器粘贴时可能清洗或重写这些属性，导致热门榜单或色条效果降级。

**建议方案**：后续通过实际粘贴测试确认，不先凭静态代码大范围简化。若确认有问题，再将关键布局改为更稳妥的块级结构：标签独立一行、标题下一行，左侧色条改为 `border-left`，减少对 `flex` 和绝对定位的依赖。

### 8. 移动端长标题和长标签的布局风险

“用户两张卡获批选留咨询”“高铁贵宾厅卡片推荐咨询”等标签较长，中英文和数字混排标题也可能造成窄屏挤压或换行不自然。

**处理结果**：已将无法识别为银行的长标题标签统一归为“其他”，避免把“用户两张卡获批选留咨询”“高铁贵宾厅卡片推荐咨询”等整段文本渲染成银行徽章；详情标题增加 `overflow-wrap:anywhere` 和 `word-break:break-word`，允许窄屏自然断行。

### 9. 热门榜单与分类详情存在内容重复

热门讨论区展示 5 条帖子，后续分类详情又完整展示这些帖子。该结构逻辑上成立，但会增加篇幅和重复阅读。

**处理结果**：保留热门榜单作为导航；详情卡优先使用 Markdown 卡头中的一句话摘要作为展示标题，完整原标题仍保留在原帖链接汇总中，减少热榜与详情区的重复。若没有摘要，则回退到原标题。

### 10. Emoji 的跨设备显示差异

栏目和卡片中使用了较多 Emoji，不同手机字体可能导致图标大小、颜色和基线略有差异。

**建议方案**：后续做多设备预览后再决定。当前可保留 Emoji，因为栏目文字本身已表达完整含义；若出现明显不一致，再减少 Emoji 使用，将视觉层级交给文字和边框样式。

## 2026-08-04 断点续跑与公众号输出修复

### 断点续跑

`微信发布.bat` 现在按步骤写入当天状态文件：

```bat
微信发布.bat --resume
```

当链接提取、详情抓取、LLM 点评或 HTML 渲染失败时，状态文件会保留已完成步骤及产物路径。启动代理后使用 `--resume`，流程从失败步骤继续，不会重复抓取已保存的数据。成功完成第 4 步后状态文件自动清理。

### LLM 输出质量与清理

- 要求模型只返回最终 Markdown，禁止输出思考过程和多个草稿版本。
- 点评目标长度调整为通常 80-140 个中文字符，要求同时包含事实、实际影响/价值或风险、原文依据。
- 生成器会从最后一个完整日报标题开始截取结构化内容，丢弃模型前置分析和后续重复改写。
- 默认模型可用时优先使用配置的默认模型。

### 回复/阅读数与热门讨论

- `backfill_stats()` 改为替换已有 `📊` 行，避免重跑时重复追加统计。
- HTML 解析器按标题从分类详情卡为热门榜单补回真实回复/阅读数，即使热门榜单行本身没有统计字段也不会显示 `?`。
- 热门榜单保留为 5 条摘要，分类区不再重复展示相同帖子；原帖链接汇总仍保留全部帖子。

从“新卡发行/申卡下卡”“权益变更”“活动优惠”中各提取一条短标题，最多组合 3 条，写入 Markdown 文件名、HTML 标题下方和元数据。当天没有对应栏目时不强行凑内容。
